    Milestone v0.4 — User Experience & Rich Discord Output¶

    Branch: milestone/v0.4-ux-campaigns
    Status: 📋 Planned
    Depends on: v0.3 ✅

    Goal¶

    Interaction with the bot feels polished. Status updates are clear and progressively updated. Summaries are presented beautifully inside Discord with campaign context baked in.

    Task Breakdown¶

    🎨 Rich Embeds¶

    Replace plain-text status messages¶

    Replace all await channel.send("🔄 …") calls with Discord Embed objects.

    Colour scheme:

    Stage Colour (hex) Label
    Recording started 0x3498db (blue) 🎙️ Recording
    Processing 0xf39c12 (orange) ⚙️ Processing
    Saving audio 0xf39c12 💾 Saving Audio
    Transcribing 0xf39c12 🗣️ Transcribing
    Summarising 0xf39c12 🧠 Summarising
    Done 0x2ecc71 (green) ✅ Done
    Error 0xe74c3c (red) ❌ Error

    Implementation: create a _make_embed(title, description, colour) helper in bot.py.

    Single "processing" message (edit, not new messages)¶

    Instead of posting a new message for each pipeline stage, post one message when processing starts and edit it as progress advances:

    msg = await channel.send(embed=_make_embed("⚙️ Processing", "Saving audio…", ORANGE))
# ... save audio ...
await msg.edit(embed=_make_embed("⚙️ Processing", "Transcribing with Whisper…", ORANGE))
# ... transcribe ...
await msg.edit(embed=_make_embed("⚙️ Processing", "Generating summary with Ollama…", ORANGE))
# ... summarise ...
await msg.edit(embed=_make_summary_embed(summary_md, note_path, campaign))

    Paginated summary embed¶

    When summary_md exceeds 4 096 characters (Discord embed body limit):

    • Split into pages at section heading boundaries (##)
    • Post each page as a separate embed with Page X / N in the footer
    • First page includes the Obsidian file path and "Open in Obsidian" button

    "Open in Obsidian" button¶

    Discord Button component with URL:

    obsidian://open?vault=<vault_name>&file=<relative_note_path>

    Derive vault_name from Path(OBSIDIAN_VAULT_PATH).name. Derive the relative note path from note_path.relative_to(OBSIDIAN_VAULT_PATH).

    🗺️ Campaign Tagging¶

    Campaign model in the sessions database¶

    Add a campaigns table (or a campaign column to the existing sessions table):

    CREATE TABLE guild_config (
    guild_id    INTEGER PRIMARY KEY,
    campaign    TEXT,           -- null when no campaign is active
    notes_folder TEXT           -- per-guild override for OBSIDIAN_NOTES_FOLDER
);

    /campaign commands¶

    Command Description
    /campaign set <name> Set the active campaign for this guild
    /campaign clear Clear the active campaign
    /campaign show Display the currently active campaign

    Require the user to have the Manage Guild permission or any role in ALLOWED_ROLE_IDS.

    Campaign-aware note saving¶

    When a campaign is active:

    1. Create a sub-folder: <OBSIDIAN_NOTES_FOLDER>/<campaign>/
    2. Include the campaign name in YAML front-matter: 
      campaign: My Campaign Name
session: 12       # auto-incremented per campaign
    3. Add the campaign slug as a tag: tags: [session-notes, ttrpg, my-campaign-name]

    Campaign embed header¶

    Include the campaign name and session number in the completion embed title: 

    ✅ My Campaign Name — Session 12

    ⌨️ /config Command¶

    Guild-admin-only command to configure the bot without touching .env.

    Sub-commands:

    Sub-command Effect
    /config model <model_name> Set the Ollama model for this guild
    /config notes-folder <path> Set the notes sub-folder for this guild
    /config show Display all current config values
    /config reset Reset to global .env defaults

    Store per-guild overrides in the guild_config table. The per-guild value takes precedence over .env.

    💬 Typing Indicator¶

    Show a Discord "typing" indicator while the pipeline is running:

    async with channel.typing():
    transcript = await asyncio.to_thread(transcribe, audio_path)

    This reassures users that the bot is working without requiring them to watch a progress bar.

    New Commands Summary¶

    Command Permission Description
    /campaign set <name> Manage Guild Set active campaign
    /campaign clear Manage Guild Clear active campaign
    /campaign show Everyone Show active campaign
    /config model <name> Manage Guild Set per-guild Ollama model
    /config notes-folder <path> Manage Guild Set per-guild notes folder
    /config show Manage Guild Show all config
    /config reset Manage Guild Reset to .env defaults

    New Environment Variables¶

    Variable Type Default Description
    ALLOWED_ROLE_IDS comma-separated int list (unset) Role IDs allowed to use /watch, /config, /campaign

    Acceptance Criteria¶

    • All pipeline status messages use colour-coded embeds
    • A single message is edited through pipeline stages (not multiple new messages)
    • Long summaries are paginated (test with a summary > 4 096 chars)
    • "Open in Obsidian" button uses the correct deep-link URL
    • /campaign set, /campaign clear, /campaign show work correctly
    • Active campaign appears in note YAML front-matter and note sub-folder path
    • /config persists per-guild settings and they take precedence over .env
    • All new commands covered by unit tests
    • CI remains green
