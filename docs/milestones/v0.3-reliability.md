# Milestone v0.3 — Reliability & Error Recovery

**Branch:** `milestone/v0.3-reliability`  
**Status:** 📋 Planned  
**Depends on:** v0.2 ✅

---

## Goal

The bot must survive common failure modes — Ollama down, disk full, network drop, bot restart mid-session — without crashing or silently discarding recorded audio.

---

## Task Breakdown

### 💾 Pipeline Resilience

#### Persist WAV file immediately

**Problem:** `finish_recording` currently holds all PCM data in memory until `/unwatch` is called.  A bot crash between the sink stop and the disk write loses the entire recording.

**Solution:**
- Call `finish_recording` synchronously inside `RecordingSink.cleanup()` (or as early as possible in the pipeline callback) so the WAV hits disk before any further processing.
- Document the recovery path clearly: if the bot restarts, the WAV file on disk is the source of truth.

#### Disk-space guard

New env var: `MIN_FREE_DISK_MB` (default: `500`)

Logic in `watch()` before starting the sink:

```python
import shutil

free_mb = shutil.disk_usage(recordings_dir).free // (1024 * 1024)
if free_mb < min_free_mb:
    await interaction.response.send_message(
        f"⚠️ Insufficient disk space ({free_mb} MB free, {min_free_mb} MB required). "
        "Free up space and try again.",
        ephemeral=True,
    )
    return
```

Test: mock `shutil.disk_usage` and assert the refusal message is sent.

#### Ollama retry with back-off

New env vars:
- `OLLAMA_MAX_RETRIES` (default: `3`)
- `OLLAMA_RETRY_DELAY_S` (default: `5`)

Logic in `summarize()`:

```python
for attempt in range(1, max_retries + 1):
    try:
        response = client.chat(...)
        return response.message.content.strip()
    except Exception as exc:
        if attempt == max_retries:
            raise
        logger.warning("Ollama attempt %d/%d failed: %s. Retrying in %ds…",
                       attempt, max_retries, exc, retry_delay)
        time.sleep(retry_delay)
```

Tests: assert the function retries the configured number of times and eventually raises on total failure.

#### Transcript fallback note

If the Ollama call fails after all retries, do not discard the transcript.  Save it as an Obsidian note with:

```yaml
---
date: YYYY-MM-DD HH:MM
tags:
  - session-notes
  - ttrpg
  - needs-summary
---
```

And a body of:
```markdown
## ⚠️ Summarisation Failed

The session was recorded and transcribed, but the AI summary could not be generated.
Run `ollama pull <model>` or check that Ollama is running, then summarise manually.

---

## Raw Transcript

<transcript text here>
```

New env var: `SAVE_TRANSCRIPT_ON_FAILURE` (default: `true`)

#### WAV file lifecycle

Env var: `DELETE_WAV_AFTER_SUCCESS` (default: `false`)

- When `true`, delete the WAV file after the full pipeline completes successfully.
- Never delete the WAV if any pipeline stage failed.
- Always log the WAV path so the user can find it.

### 🗄️ Session State (SQLite)

New module: `src/sessions.py`

Schema:

```sql
CREATE TABLE sessions (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    guild_id    INTEGER NOT NULL,
    started_at  TEXT NOT NULL,   -- ISO 8601
    ended_at    TEXT,
    status      TEXT NOT NULL,   -- 'recording' | 'processing' | 'done' | 'failed'
    wav_path    TEXT,
    note_path   TEXT,
    error       TEXT
);
```

Operations:
- `create_session(guild_id) -> int` — inserts a new `recording` row
- `update_session(session_id, **kwargs)` — update any field
- `get_recent_sessions(guild_id, limit=10) -> list[Session]`
- `get_interrupted_sessions() -> list[Session]` — status `recording` with no `ended_at`

Database path env var: `DB_PATH` (default: `~/.rpgwatcher/sessions.db`)

On bot startup (`on_ready`), check for interrupted sessions and log a warning listing them.

Tests: use `tmp_path` to create an in-memory or temp-file SQLite DB; test all CRUD operations.

### 📋 Structured Logging

#### JSON log format

New env var: `LOG_FORMAT` (`text` | `json`, default: `text`)

When `json`:
- Use `python-json-logger` or a custom `logging.Formatter` to emit JSON lines
- Each line includes `timestamp`, `level`, `logger`, `message`, and any extra fields passed via `logger.info("msg", extra={...})`

#### Session correlation ID

In `_on_recording_finished`, generate a UUID4 `session_id` at the start and attach it to every log call for that session:

```python
import uuid
session_id = str(uuid.uuid4())
logger.info("Pipeline started", extra={"session_id": session_id, "guild_id": guild.id})
```

## New Environment Variables

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `MIN_FREE_DISK_MB` | int | `500` | Minimum free disk (MB) required to start recording |
| `OLLAMA_MAX_RETRIES` | int | `3` | Max Ollama call attempts before giving up |
| `OLLAMA_RETRY_DELAY_S` | int | `5` | Seconds to wait between Ollama retries |
| `SAVE_TRANSCRIPT_ON_FAILURE` | bool | `true` | Save raw transcript note if summarisation fails |
| `DELETE_WAV_AFTER_SUCCESS` | bool | `false` | Delete WAV file after successful pipeline |
| `DB_PATH` | path | `~/.rpgwatcher/sessions.db` | SQLite database file location |
| `LOG_FORMAT` | string | `text` | Log output format: `text` or `json` |

## Acceptance Criteria

- [ ] Bot refuses to start recording when disk space is below `MIN_FREE_DISK_MB`
- [ ] Ollama call retries up to `OLLAMA_MAX_RETRIES` times with `OLLAMA_RETRY_DELAY_S` delay
- [ ] On total Ollama failure, transcript is saved to Obsidian tagged `#needs-summary`
- [ ] WAV file is never deleted if any pipeline stage fails
- [ ] Sessions table is created and populated on every `/watch` + `/unwatch` cycle
- [ ] `/status` reports Ollama reachability, Whisper backend, vault and recordings dir
- [ ] All new functionality covered by unit tests
- [ ] CI remains green
